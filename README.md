# Beetroot EMB 4

Навчальний проєкт для STM32F411CE (плата BlackPill), що демонструє черги FreeRTOS.

## Що демонструє проєкт

`queueTx` надсилає команди через чергу таску `queueRx`, який керує трьома LED-виходами в циклі:

1. Увімкнути LED1 (PA1), зачекати 1 с.
2. Увімкнути LED2 (PA2), зачекати 1 с.
3. Увімкнути LED3 (PA3), зачекати 1 с.
4. Вимкнути LED3, LED2, LED1 з інтервалом 1 с між командами.

Після вимкнення LED1 таск чекає ще 1 с і повторює цикл.

Під'єднайте кожен пін до анода світлодіода через окремий резистор 330–1000 Ом, катоди — до GND. Вбудований світлодіод PC13 не використовується демонстрацією. Світлодіоди працюють і без USB.

Порти й піни задаються макросами у `Src/app/main_app.cpp`; усі три піни мають належати одному порту. При зміні порту також змініть макрос увімкнення його тактування `LED_GPIO_CLK_ENABLE()`.

## IPC: черга команд

Кожен елемент черги — структура `LedCommand` з номером світлодіода (`LED1`, `LED2` або `LED3`) і бажаним станом (`GPIO_PIN_SET` або `GPIO_PIN_RESET`). Усі елементи мають однаковий розмір.

### Як працює приклад

1. `main_cpp()` вимикає світлодіоди та викликає `xQueueCreate(4U, sizeof(LedCommand))`: створюється черга місткістю чотири команди.
2. `queueTx` формує структуру та викликає `xQueueSend(led_queue, &command, portMAX_DELAY)`. Черга копіює структуру і додає її в кінець. Якщо черга повна, таск чекає вільного місця.
3. Між надсиланнями `queueTx` викликає `osDelay(1000U)`. Це 1000 тактів; при `configTICK_RATE_HZ = 1000` у цьому проєкті — приблизно 1 с.
4. `queueRx` викликає `xQueueReceive(led_queue, &command, portMAX_DELAY)`. Він чекає, якщо черга порожня, інакше отримує та видаляє найстарішу команду.
5. Отримувач вибирає пін за номером LED, встановлює його стан і виводить лог, наприклад `[queueRx] LED1 ON`.

Черга зберігає окремі команди в порядку надсилання, зокрема повторні команди. Для неї виділяється пам'ять під блок керування і копії елементів. У прикладі один відправник та один отримувач, але одна черга може використовуватися кількома тасками.

Щоб побачити накопичення команд, можна тимчасово додати `osDelay(2000U)` наприкінці циклу `queueRx`: відправник працюватиме швидше за отримувача, черга заповниться, а `xQueueSend()` чекатиме місця. Команди не об'єднаються і будуть оброблені по черзі; інтервали між діями LED при цьому зміняться.

### Черга з переривання

З обробника переривання (ISR) для надсилання використовують `xQueueSendFromISR()`, а не `xQueueSend()`. Наприклад, така функція додає команду ввімкнення LED1 до тієї самої черги:

```cpp
// Приклад для main_app.cpp, де доступні LedCommand і led_queue.
extern "C" BaseType_t QueueLed1OnFromISR(void)
{
    const LedCommand command = {LED1, GPIO_PIN_SET};
    BaseType_t higher_priority_task_woken = pdFALSE;

    BaseType_t result = xQueueSendFromISR(
        led_queue, &command, &higher_priority_task_woken);
    portYIELD_FROM_ISR(higher_priority_task_woken);
    return result;
}
```

- `xQueueSendFromISR()` копіює команду в кінець черги. Локальна змінна `command` після виклику більше не потрібна.
- Якщо розблоковано таск з вищим пріоритетом, `higher_priority_task_woken` стане `pdTRUE`; `portYIELD_FROM_ISR()` запитає перемикання контексту після завершення ISR.
- ISR не може чекати вільного місця. Якщо черга повна, функція повертає `errQUEUE_FULL`; викликач має перевірити результат і обробити втрату команди, наприклад зафіксувати помилку для подальшої обробки в таску. `printf()` з ISR викликати не потрібно.

Це лише приклад: поточна програма не налаштовує переривання і не викликає цю функцію. Для використання потрібно оголосити її для обробника, налаштувати джерело та підтверджувати його переривання відповідно до периферії. Вмикайте ISR лише після створення черги та запуску планувальника. Якщо одночасно працює `queueTx`, його команди та команди ISR надходитимуть до однієї черги.

У цьому проєкті `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 5`: ISR, який викликає FreeRTOS API, повинен мати числовий пріоритет NVIC від 5 до 15. Пріоритети 0–4 вищі й не можуть викликати API `FromISR`. Використовуйте групування пріоритетів NVIC, сумісне з FreeRTOS.

## Апаратна конфігурація

- MCU: STM32F411CEUx
- Framework: STM32Cube HAL
- Збірка та завантаження: PlatformIO, ST-Link

## Збірка

```
pio run
pio run -t upload
```

## Структура

- `Src/app/main_app.cpp` — черга й таски керування світлодіодами
- `Inc/FreeRTOSConfig.h` — конфігурація FreeRTOS
- `Src/main.c` — ініціалізація та запуск планувальника
