# Beetroot EMB 4

Навчальний проєкт для STM32F411CE (плата BlackPill), що демонструє FreeRTOS Task Notification.

## Що демонструє проєкт

`notifyTx` надсилає біти команд таску `notifyRx`, який керує трьома LED-виходами в циклі:

1. Увімкнути LED1 (PA1), зачекати 1 с.
2. Увімкнути LED2 (PA2), зачекати 1 с.
3. Увімкнути LED3 (PA3), зачекати 1 с.
4. Вимкнути LED3, LED2, LED1 з інтервалом 1 с між командами.

Після вимкнення LED1 таск чекає ще 1 с і повторює цикл.

Під'єднайте кожен пін до анода світлодіода через окремий резистор 330–1000 Ом, катоди — до GND. Вбудований світлодіод PC13 не використовується демонстрацією. Світлодіоди працюють і без USB.

Порти й піни задаються макросами у `Src/app/main_app.cpp`; усі три піни мають належати одному порту. При зміні порту також змініть макрос увімкнення його тактування `LED_GPIO_CLK_ENABLE()`.

## IPC: Task Notification Bits

Цей приклад показує notification bits як команди керування світлодіодами:

| Біт | Команда | Дія |
|-----|---------|-----|
| 0 | `NOTIFY_LED1_ON` | Увімкнути LED1 |
| 1 | `NOTIFY_LED1_OFF` | Вимкнути LED1 |
| 2 | `NOTIFY_LED2_ON` | Увімкнути LED2 |
| 3 | `NOTIFY_LED2_OFF` | Вимкнути LED2 |
| 4 | `NOTIFY_LED3_ON` | Увімкнути LED3 |
| 5 | `NOTIFY_LED3_OFF` | Вимкнути LED3 |

### Як працює приклад

1. `main_cpp()` встановлює початковий стан LED «вимкнено» та створює `notifyRx`. Його handle потрібен відправнику, тому `notifyTx` створюється другим.
2. `notifyTx` викликає `xTaskNotify(notification_receiver_handle, notification_bit, eSetBits)`. Режим `eSetBits` додає біт команди до значення отримувача операцією OR.
3. Між командами `notifyTx` викликає `osDelay(1000U)`. Це 1000 тактів; при `configTICK_RATE_HZ = 1000` у цьому проєкті — приблизно 1 с.
4. `notifyRx` чекає у `xTaskNotifyWait(0U, NOTIFY_LED_MASK, &notification_bits, portMAX_DELAY)`. Перший аргумент не очищає біти на вході; другий задає біти для очищення після отримання; третій отримує значення **до** очищення; четвертий задає необмежене очікування.
5. Таск проходить біти від молодшого до старшого, обробляє кожен через `switch` і змінює відповідний GPIO. На час очікування він не займає процесор.

Після кожної команди `notifyRx` виводить лог, наприклад `[notifyRx] LED1 ON`, через USB CDC (віртуальний COM-порт). Логи, надіслані до підключення USB або коли передача зайнята, можуть бути втрачені; на роботу світлодіодів підключення USB не потрібне.

Notification зберігається в control block отримувача, тому окрема черга чи IPC-буфер не створюються. `GPIO_PIN_SET` вмикає, а `GPIO_PIN_RESET` вимикає LED за описаної вище схеми підключення.

Якщо до отримання надійшло кілька команд, їхні біти об'єднуються; цикл обробляє кожен установлений біт через `switch`. Біти не зберігають кількість і порядок команд: якщо для одного LED одночасно встановлені ON та OFF, у цьому прикладі останньою застосовується OFF.

### Notification з переривання

З обробника переривання (ISR) замість `xTaskNotify()` використовуйте `xTaskNotifyFromISR()`. Наприклад, функція нижче встановлює біт увімкнення LED1 для наявного `notifyRx`:

```cpp
// Приклад для розміщення в main_app.cpp, де доступні handle і біт команди.
extern "C" void NotifyLed1FromISR(void)
{
    BaseType_t higher_priority_task_woken = pdFALSE;
    BaseType_t result = xTaskNotifyFromISR(
        notification_receiver_handle, NOTIFY_LED1_ON, eSetBits,
        &higher_priority_task_woken);
    configASSERT(result == pdPASS);
    portYIELD_FROM_ISR(higher_priority_task_woken);
}
```

`higher_priority_task_woken` встановлюється в `pdTRUE`, якщо notification розбудила таск з вищим пріоритетом. `portYIELD_FROM_ISR()` у такому разі запитує перемикання контексту після завершення переривання. Обробка біта та `printf()` залишаються в `notifyRx`, а не в ISR.

Це лише приклад: поточна програма не налаштовує джерело переривання і не викликає цю функцію. Для використання потрібно оголосити її для обробника, налаштувати та підтвердити відповідне апаратне переривання і викликати функцію з ISR. Вмикайте переривання лише після створення `notifyRx`, коли його handle вже дійсний. Одночасна робота ISR і `notifyTx` може об'єднувати їхні біти.

Для цього проєкту `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 5`: ISR, що викликає FreeRTOS API, має мати числовий пріоритет NVIC від 5 до 15. Пріоритети 0–4 вищі й не можуть викликати навіть API з суфіксом `FromISR`. Використовуйте налаштування групування пріоритетів NVIC, сумісне з FreeRTOS.

## Апаратна конфігурація

- MCU: STM32F411CEUx
- Framework: STM32Cube HAL
- Збірка та завантаження: PlatformIO, ST-Link

## Збірка

```
pio run
pio run -t upload
```

## Структура

- `Src/app/main_app.cpp` — таски та notification-команди для світлодіодів
- `Inc/FreeRTOSConfig.h` — конфігурація FreeRTOS
- `Src/main.c` — ініціалізація та запуск планувальника
