# Beetroot EMB 4

Навчальний проєкт для STM32F411CE (плата BlackPill): драйвери I2C та SPI і приклад зчитування годинника DS1307.

## Що демонструє проєкт

Прошивка в `main_cpp()`:

1. Ініціалізує I2C1 (100 кГц).
2. Сканує шину та виводить адреси всіх знайдених пристроїв.
3. Перевіряє наявність DS1307 (`0x68`).
4. Раз на секунду зчитує 8 регістрів (`0x00`–`0x07`) і виводить їх у hex через `printf`.

Модуль `i2c` сам налаштовує тактування, GPIO і HAL MSP, тому окреме налаштування I2C у CubeMX не потрібне. Хендл `I2C_HandleTypeDef` створює і зберігає застосунок.

## Апаратна конфігурація

- I2C: I2C1, master, PB6 (SCL), PB7 (SDA), 100 кГц у прикладі, до 400 кГц
- MCU: STM32F411CEUx
- Framework: STM32Cube HAL
- Збірка та завантаження: PlatformIO, ST-Link

### Підключення DS1307

Під'єднайте SCL до PB6, SDA до PB7, а також живлення та GND. Усередині STM32 увімкнені слабкі підтягувальні резистори, але для надійної роботи на шині потрібні зовнішні (зазвичай вони вже є на модулі DS1307).

## Збірка

```
pio run
pio run -t upload
```

## API модулів

### I2C (`Inc/i2c/i2c.h`)

Усі функції приймають 7-бітну адресу пристрою (без зсуву) і працюють у блокувальному режимі.

| Функція | Призначення |
|---------|-------------|
| `I2C_Init(&hi2c, I2C1, speed_hz)` | Ініціалізація I2C1 (master, 7-бітна адресація, до 400 кГц) |
| `I2C_Probe(&hi2c, addr, timeout)` | Перевірка, чи відповідає пристрій за адресою |
| `I2C_Scan(&hi2c, found, max_found, &count, timeout)` | Пошук усіх пристроїв в діапазоні `0x08`–`0x77`; `count` — загальна кількість знайдених |
| `I2C_ReadRegister(&hi2c, addr, reg, data, size, timeout)` | Читання регістрів з 8-бітною адресою регістра |
| `I2C_Transmit` / `I2C_Receive` | Пряма передача й прийом даних |

Приклад:

```c
static I2C_HandleTypeDef hi2c1;

I2C_Init(&hi2c1, I2C1, 100000U);

uint8_t found[16], count;
I2C_Scan(&hi2c1, found, sizeof(found), &count, 10);

uint8_t regs[8];
I2C_ReadRegister(&hi2c1, 0x68, 0x00, regs, sizeof(regs), 100);
```

### SPI (`Inc/spi_master/spi_master.h`, `Inc/spi_slave/spi_slave.h`)

Обидва драйвери використовують HAL у блокувальному режимі, 8-бітні слова,
MSB-first та SPI mode 0 (CPOL=0, CPHA=0). Master використовує SPI1:
SCK=PA5, MISO=PA6, MOSI=PA7; NSS керується програмно, тому вибір пристрою
(CS) має виконувати застосунок. Slave використовує SPI2:
NSS=PB12, SCK=PB13, MISO=PB14, MOSI=PB15; NSS налаштований як апаратний вхід.

| Функція | Призначення |
|---------|-------------|
| `SPI_Master_Init(&hspi, SPI1, prescaler)` | Ініціалізація master; prescaler — `SPI_BAUDRATEPRESCALER_2` ... `_256` |
| `SPI_Slave_Init(&hspi, SPI2)` | Ініціалізація slave |
| `SPI_*_Transmit` / `SPI_*_Receive` | Блокувальна передача або прийом |
| `SPI_*_TransmitReceive` | Повнодуплексний обмін |
| `SPI_*_DeInit` | Вимкнення SPI та звільнення його GPIO |

Функції передавання повертають `HAL_StatusTypeDef` і приймають timeout у
мілісекундах. Slave-функції очікують тактування від master і блокують поточний
контекст до завершення обміну або timeout. Для тесту SPI1↔SPI2 на одній платі
slave-операцію потрібно запустити в окремому контексті до початку обміну
(наприклад, у задачі RTOS); драйвери не запускають slave автоматично у фоні.

### Емулятор BME280 через SPI

`Src/spi_slave/bme280_spi_emulator.c` моделює регістрову карту BME280, включно
з ID `0x60` за адресою `0xD0`, калібрувальними значеннями й фіксованими сирими
даними вимірювань. У SPI-команді старший біт байта адреси задає читання/запис,
тому на шині використовуються 7 молодших бітів адреси регістра; API емулятора
приймає адреси з карти BME280 і нормалізує їх так само. Читання підтримує
послідовне автоінкрементування адреси; запис змінює керувальні регістри `0xF2`,
`0xF4` та `0xF5`, а команда soft reset `0xB6` за адресою `0xE0` відновлює
значення за замовчуванням.

```c
static SPI_HandleTypeDef hspi2;
static BME280_SPI_Emulator_HandleTypeDef bme280;

SPI_Slave_Init(&hspi2, SPI2);
BME280_SPI_Emulator_Init(&bme280, &hspi2);
BME280_SPI_Emulator_Start(&bme280);
```

Цей запуск емулятора також є в `Src/app/main_app.cpp`: під час старту
прошивки ініціалізується SPI2 і виводиться статус емулятора через `printf`;
після цього продовжується I2C-приклад DS1307.

Під'єднайте SPI1 до SPI2: PA5→PB13 (SCK), PA6←PB14 (MISO), PA7→PB15 (MOSI),
а GPIO master для CS — до PB12 (NSS). CS потрібно утримувати низьким протягом
командного байта й усіх байтів даних. Емулятор обслуговує SPI2 перериваннями;
він призначений для невисокої частоти SPI і навчальних тестів, а не для
таймінг-критичних пристроїв. Сирі вимірювання є фіксованими тестовими даними,
не результатом обчислення фізичних величин.

## Структура

- `Src/app/main_app.cpp` — приклад: сканування I2C і читання регістрів DS1307
- `Src/i2c/i2c.c`, `Inc/i2c/i2c.h` — I2C-модуль
- `Src/spi_master/spi_master.c`, `Inc/spi_master/spi_master.h` — SPI1 master
- `Src/spi_slave/spi_slave.c`, `Inc/spi_slave/spi_slave.h` — SPI2 slave
- `Src/spi_slave/bme280_spi_emulator.c`, `Inc/spi_slave/bme280_spi_emulator.h` — емулятор регістрів BME280
- `Src/main.c` — запуск HAL, системного тактування та периферії
- `Src/stm32f4xx_it.c` — обробники переривань
- `Src/stm32f4xx_hal_msp.c` — низькорівневе налаштування іншої периферії
- `Inc/stm32f4xx_hal_conf.h` — конфігурація HAL (увімкнено I2C, SPI)
